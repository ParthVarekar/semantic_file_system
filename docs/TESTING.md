# Testing and verification

All tests use synthetic files generated by `lfi.synthetic.build_corpus` inside pytest's
temporary directory, with a private `LFI_HOME`. They never touch real personal files or the
real app index. Destructive paths (quarantine, purge, Recycle Bin, cross-drive copy) run only on
those synthetic files; the Recycle Bin call is mocked so nothing reaches your real bin.

The synthetic corpus includes: DOCX/PPTX/XLSX/PDF (multi-page, with metadata), an
RC4-encrypted PDF, corrupt DOCX/PDF, random binary, UTF-8 with Devanagari and accents, HTML with
script, YAML/JSON/CSV/ipynb, JPEG with EXIF camera, PNG, a screen-sized screenshot, a resized
and re-compressed near-duplicate image, three exact duplicates (`(1)`, `- Copy`, `_copy`), old
installers (backdated mtime), a ZIP, a `.crdownload`, an Office `~$` lock file, an empty file, a
3 MB sparse video, a software project with `.git` and `node_modules`, a >260-character path,
an NTFS junction, and a hidden+system `desktop.ini`.

### Review and fixes (2026-10-27)

A reproduce-first review (one reviewer per subsystem, each finding reproduced with a script before
it counted) found and the fixes closed: path aliases and junction swaps that could move files
outside the selected folders, cloud placeholders being read, a privacy-mode setting that corrupted
the full-text index, filters that missed matches in big libraries, a CLI that could not download
models, recovery that could interfere with another window's batch, reversed result tables, and
about 40 smaller issues. Every fix has a regression test in the suites above; for the fixes in
`test_paths_and_recovery.py`, `test_index_robustness.py`, `test_search_filters.py`,
`test_dupes_feedback.py` and `test_ui_regressions.py`, the tests were also run against the code
before the fix and failed there.

Additional manual/automated verification:

* GUI driven headlessly through every page (index → search → cleanup → duplicates → organize →
  quarantine three duplicates → activity → settings), with screenshots inspected.
* CLI workflow on the demo corpus: index → search → dupes → cleanup → organize `--apply` (11
  moves) → `undo` (all moved back, created folders removed) → quarantine 3 → restore with an
  occupied original path (restored as `(restored)`, nothing overwritten).
* `scripts\setup.ps1 -Gpu -Dev -NoModel -VenvDir .venv-gpu` executed: DirectML provider active.
* Image search driven through the real GUI (offscreen): Images scope returned the receipt photo
  first for "the paper receipt from the grocery store"; thumbnails decoded off the GUI thread.
* Packaged `lfi.exe`: 16 images understood in the frozen worker; `--scope images "a qr code"` → the QR image.
* Rebuilt package (2026-10-27): CLI round trip on a folder named `corpus ünï 📁` with output piped
  (39 files, 4 images; Devanagari result printed intact); image search found the sunset as a strong
  picture match; `lfi.exe undo 999` → `error:` and exit 2; `LocalFileIntelligence.exe --quick`
  registered Alt+Shift+Space, showed on the hotkey message, and a second start reused it; the main
  window started.
* Quick search on the real desktop (not offscreen): hotkey registration, show/hide toggle via the
  WM_HOTKEY message Windows sends, single instance. On this PC Alt+Space and Ctrl+Alt+Space were
  already taken by other programs, which is why the default is Alt+Shift+Space with fallbacks.
* Search quality: 75 vague queries with a held-out half (BENCHMARKS.md section 6).

## Not verified / remaining on real hardware

* CUDA execution provider (only DirectML was tested for GPU).
* Real OneDrive online-only placeholders (attribute logic is unit-level; no OneDrive account
  was used).
* FAT32/exFAT and network (SMB) drives; ReFS.
* Very large real-world collections (>100k files) and very large single files (multi-GB
  hashing was exercised only through sparse files).
* Packaged `.exe` behaviour beyond start-up smoke testing (see PACKAGING.md).
* High-DPI and screen-reader accessibility review (layout was checked at 150 % scaling on 1366x768,
  screen readers were not).
* Quick search with a physical key press and typing on the real desktop (verified through the
  message Windows sends for the hotkey; no keystrokes were injected into the desktop session).
